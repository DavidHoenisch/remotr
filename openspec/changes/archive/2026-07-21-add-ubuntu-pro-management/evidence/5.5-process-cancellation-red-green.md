# Task 5.5 process cancellation and timeout evidence

- Verification ID: OS-UPM-030.
- Public seam: `executor.Check` on the Ubuntu Pro handler; protected mutation calls share the same API process boundary.
- Red cancellation: a canceled Check used the legacy non-context runner and returned generic `probe_failed` instead of reaching a cancelable process boundary.
- Green cancellation: context-aware read and protected-stdin process interfaces carry cancellation into the operating-system process boundary; Check maps it to stable `ubuntu_pro_canceled` without process diagnostics.
- Red deadline: a synthetic caller deadline was accepted by a legacy runner that could not terminate the process, and Check incorrectly returned compliant.
- Green deadline: deadline-bearing calls fail closed unless the injected runner implements the matching context-aware read or protected-stdin interface. Production sanitized runners implement both with `exec.CommandContext`.
- Deterministic timeout: the test injects the timeout factory and returns a fixed already-expired context, verifies the exact bounded duration, and observes stable `ubuntu_pro_timeout`; cancellation and timeout tests contain no sleeps.
