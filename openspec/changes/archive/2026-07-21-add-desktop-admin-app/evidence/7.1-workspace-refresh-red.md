- Test layers: Testing Library navigation and keyboard interaction,

  assertions, stale timestamp/orientation assertions, and permitted editor
  input preservation
- Red command: `pnpm exec vitest run src/refresh/WorkspaceRefresh.test.tsx
  --reporter=dot`
- Red result: intended failure (`1` file, `3` failing tests). Scheduled ticks
  and visibility resume made zero workspace requests, and the shell exposed no
  `Refresh workspace` control because no refresh controller was mounted.

The success/failure contract holds the first request unresolved across two
thirty-second ticks to require a one-request guard. The old Endpoint must remain
visible and the new one absent until the complete replacement resolves. A
later controlled connection failure must retain only the last successful row
while labeling the evidence stale with the independently known loaded and
failed timestamps.

The visibility contract begins hidden, advances across three complete
intervals without a request, then requires exactly one immediate request on the
hidden-to-visible transition. Another tick while that request is unresolved
must not overlap it; the next visible tick after resolution may refresh.

The explicit/shortcut contract requires a labeled shell refresh control and
the conventional Linux desktop `Ctrl+R` shortcut outside an editor. The same
keystroke in the Endpoint search input must neither request a refresh nor alter
its current text. All time advancement and visibility changes are synchronous
manual fixture operations; the tests contain no real timers or sleeps.
