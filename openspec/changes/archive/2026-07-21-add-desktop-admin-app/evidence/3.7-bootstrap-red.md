# Task 3.7 bootstrap-service red evidence

- Verification IDs: `OS-DOA-011`, `OS-DOA-012`, `OS-DOA-013`
- Public seam: typed desktop bootstrap service
- Test layers: focused native Go integration test over controlled HTTPS/TLS,
  protected temporary filesystem state, and one injected OS persistence-failure
  boundary
- Command: `go test ./... -run '^TestBootstrapService' -count=1`
- Result: intended red (`exit 1`)

The compiler reported that the expected bootstrap seam was absent, including
`NewBootstrapService`, `BootstrapAttempt`, `BootstrapFailureKind`,
`WithCredentialPersistence`, and the classified failure constants.

The committed tests use a mutable synthetic token buffer and a real issued
private-key PEM canary. They require success to persist only the existing
owner-protected credential layout and then verify `/v1/admin/me`; API rejection
to persist nothing; cancellation to propagate without persistence; and an
injected partial certificate/key write to be completely cleaned. Every terminal
path must zero the token buffer, and failures/results must exclude token,
private-key, response-body, path, and persistence-error canaries. Task 3.8 adds
the minimum exchange and transactional persistence behavior needed to make the
slice green.
