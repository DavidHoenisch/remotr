# 13.9 Flatpak tagged release — red evidence

- Verification IDs: `OS-DOA-002` and `OS-DOA-018`.
- Public seams: the Linux desktop package manifest and lifecycle, then the
  tagged GitHub Release asset set produced by GoReleaser.
- Selected layers: focused manifest contract, deterministic package lifecycle
  test, release-manifest contract, tagged-release workflow contract, exact
  native Flatpak build/install/launch/remove smoke, and the root regression
  suite.

## Intended red

The work proceeded as six vertical red-to-green slices:

1. `go test ./desktop -run '^TestFlatpakManifestPackagesLinuxDesktopWithRequiredSandboxAccess$'`
   failed because no Flatpak manifest existed.
2. `go test ./internal/desktoplayout -run '^TestAdvertisedFlatpakHasNativeInstallLifecycleEvidence$'`
   failed because the package inventory had no Flatpak target or lifecycle
   command.
3. `go test ./internal/desktoplayout -run '^TestDesktopReleaseManifestAcceptsEvidencedFlatpakReleaseAsset$'`
   failed because the release-manifest generator rejected GitHub Release
   publication and Flatpak filenames.
4. `go test ./internal/desktoplayout -run '^TestTaggedReleaseBuildsAndPublishesEvidencedFlatpak$'`
   failed because the tagged workflow did not build a Flatpak and GoReleaser
   did not checksum or upload one.
5. The focused manifest and lifecycle tests failed when tightened to require
   the exact `~/.config/remotr` mount: the earlier XDG-private launcher shape
   did not preserve saved absolute profile references, and the smoke did not
   read the CLI's actual home-relative path.
6. The focused lifecycle test failed when it required an inaccessible secret
   canary outside `~/.config/remotr`; the smoke had positive config evidence
   but no negative sandbox, redaction, or cleanup assertion.

These are the intended public-contract failures: a package is not advertised
until its manifest, exact lifecycle evidence, truthful release classification,
and tagged upload path exist together.

## Green and regression evidence

- The Flatpak manifest contract pins `org.gnome.Platform//50` and
  `org.gnome.Sdk//50`, installs the production Wails binary and required desktop
  metadata, and limits sandbox access to display, graphics, IPC, network, and
  the exact `~/.config/remotr` directory used by the CLI and saved desktop
  profiles. The real smoke reads a non-secret host-config sentinel through the
  mount, proves a secret canary outside that directory is unreadable and absent
  from the bundle/log, then proves both host sentinels remain unchanged after
  uninstall.
- The deterministic lifecycle test proves the advertised target routes through
  build, bundle, install, payload/version inspection, observed native launch,
  remove, and absence checks.
- The release-manifest contract accepts only the unsigned, release-eligible
  Linux/amd64 Flatpak GitHub Release target and retains the unsigned,
  non-release-eligible DEB development target.
- The tagged workflow completes the exact native Flatpak check before
  GoReleaser, and GoReleaser adds the bundle, evidence manifest, and current
  machine-readable CLI parity inventory to the release and `checksums.txt`.

The exact native command
`make desktop-flatpak-release-check DESKTOP_VERSION=0.0.0-flatpak.local`
passed. It built the production Wails binary, composed AppStream metadata,
created a 6,534,264-byte bundle, installed it in an isolated user directory,
checked its payload and embedded identity, observed the `Remotr Desktop` native
window under Xvfb, removed it, proved it absent, and validated the generated
release manifest. The local evidence bundle SHA-256 was
`bdb94b1080fe149222bc19fd7cd3a30f0354b0398e37991aec1f0c55a897c290`.

`openspec validate add-desktop-admin-app --strict`, the strict documentation
build, and traceability lint passed. `make desktop-test` passed the desktop Go
suite, the dev-tag CSP seam, and all 33 frontend test files (72 tests after
review fixes). `make test` passed all 37 discovered fuzz seed targets and the
complete root Go suite.
