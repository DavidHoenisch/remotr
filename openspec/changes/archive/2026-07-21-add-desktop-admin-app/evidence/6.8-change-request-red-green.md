The Change request inventory retains the exact server-provided identifiers,
Fleet, Release ref, risk, lifecycle, target count, approval count/threshold,
and update timestamp. A pending request remains `pending`; the presentation
does not infer either approval or completion from counts or adjacent evidence.

Selecting a request loads an identity-checked, read-only detail record. The
surface presents the artifact and resource plan, authorization group and
approval evidence, compatibility and preflight evidence, reported outcomes,
and chronological history as bounded structured fields. The service response
does not expose a rollout-window value, so the field is explicitly labeled
`Not reported`. Authorization, pause, resume, revoke, baseline-promotion, and
baseline-adoption controls are absent from the first-release surface.

At a controlled 1100-by-720 browser viewport, the document remained exactly at
the viewport extents. The 1,120-pixel evidence table stayed inside its
826-pixel horizontal scroller with the action column pinned. The 1,404-pixel
detail record stayed inside the 596-pixel overlay scroller, whose bounds were
380 to 1,100 pixels horizontally and 48 to 720 pixels vertically. The browser
reported no application errors; only the development Electron CSP warning and
normal Vite/React development messages were present.
