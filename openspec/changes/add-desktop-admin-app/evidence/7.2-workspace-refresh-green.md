The reusable refresh controller owns one in-memory workspace snapshot and one
in-flight request. A successful response replaces the complete snapshot in one
state transition. An interval tick, explicit shell action, retry action,
visibility resume, or `Ctrl+R` all enter the same guarded request path, so
ticks and shortcuts cannot overlap a pending request.

Refresh failure retains the last successful snapshot and records classified
safe message/guidance plus the injected clock's failure timestamp. The shell
labels this data `Stale workspace evidence` and shows the active section's
server-provided loaded time and the controlled failure time; it does not label
the rows current. A later success clears the stale record.

The scheduler checks visibility on every interval and makes no hidden-window
request. A hidden-to-visible transition may enter the guarded request path
immediately. `Ctrl+R` prevents native reload and refreshes outside an editor;
inside input, textarea, select, contenteditable, or textbox context it prevents
native reload without refreshing or changing the field. StrictMode effect
setup/cleanup replay leaves exactly one active scheduler/subscription.

At a controlled 1100-by-720 browser viewport, the stale banner occupied the
expected 248-to-1,076 horizontal bounds and fit its 824-pixel client width with
an equal scroll width. The retained Overview fit inside the remaining
466-pixel content height without vertical overflow. The document remained
exactly at the viewport extents, both Refresh and Retry refresh were accessible,
and the browser reported no application errors.
