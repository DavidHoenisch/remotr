# 13.8 Desktop release publication — red evidence

- Verification IDs: `OS-DOA-001`, `OS-DOA-018`, and `OS-DOA-019`.
- Public seam: the tagged CLI/agent release, independent desktop development
  publication workflow, package target policy, and published maintainer/rollback
  documentation.
- Selected layers: focused release-contract test, complete desktop layout
  package, strict documentation build, strict OpenSpec validation, and the root
  regression suite.

## Intended red

Command:

`env GOCACHE=/tmp/remotr-gocache mise exec -- go test ./internal/desktoplayout -run '^TestDesktopDevelopmentPublicationIsAdditiveLinuxOnlyAndReversible$' -count=1`

The focused contract failed because the development snapshot upload was not an
explicitly optional workflow-dispatch action and the maintainer/reference
documentation did not yet state the independent tagged-release boundary,
licensing/signing block, or distribution-only rollback procedure. This is the
intended release-integration red.

## Green and regression evidence

- The focused release contract passes: the tagged GoReleaser path remains
  desktop-independent, and the read-only Linux desktop workflow accepts an
  explicit `publish_development_snapshot` switch while retaining all checks.
- Python YAML parsing accepts `.github/workflows/desktop.yml` after the input and
  conditional upload were added.
- The package target remains truthfully classified as one unsigned,
  non-release-eligible Linux/amd64 DEB development artifact; no GitHub Release
  upload, signing secret, macOS runner, or Windows runner is configured.
- `go test ./internal/desktoplayout -count=1` passes the complete release-layout
  and documentation contracts.
- `mkdocs build --strict --quiet` and
  `openspec validate add-desktop-admin-app --strict` pass.
- `make test` passes all 37 discovered fuzz seed targets and the complete root Go
  suite.

The release guide and support reference state that publication can stop without
a server/API/database migration or Operator credential rotation/relocation. A
future production desktop release remains blocked on a reviewed redistribution
license, signing/distribution policy, release-eligible target declaration, and
exact native evidence.
