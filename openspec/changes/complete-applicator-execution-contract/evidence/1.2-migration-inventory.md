# Applicator execution-contract migration inventory

Task 1.2 baseline, captured 2026-07-17. This inventory is deliberately broader
than the set that will ultimately become transactional: it records every
registered provider's observable rollback advertisement, every accepted
resource field, every generic exposure/persistence boundary, and every source
of a `changecontrol.FleetPlan`. Later tasks must update this inventory when a
provider is migrated or honestly downgraded.

migration before the provider rows above can use a common transaction handle.

### Task 3.2 field-policy update — 2026-07-18

Every path above plus the shared `kind`, `name`, and `ResourceMeta` paths now
has an explicit `FieldDescriptor` in
`internal/resourceregistry/field_policies.go`. Paths are derived independently
from the exact typed Go schema used by YAML `KnownFields` decoding. Registration
fails for a missing, extra, duplicate, or invalid descriptor, and the dedicated
`TestDefaultFieldPoliciesCoverStrictSchemas` linter compares the two complete
sorted path sets for every registered kind.

| Projection | Permitted field class | Safe external shape |
| --- | --- | --- |
| `value` | public only | Original typed value. |
| `metadata` | sensitive-metadata only | Classified metadata for a sink that admits that class. |
| `fingerprint` | sensitive-metadata only | Already-safe digest/fingerprint identity. |
| `count` | sensitive-metadata only | Collection cardinality without member values. |
| `presence` | sensitive-metadata or secret | Boolean presence only. |
| `reference` | secret only | Approved provider/name/version reference metadata, never resolved secret bytes. |
| `omit` | sensitive-metadata or secret | No value leaves the execution boundary. |

Important reviewed outcomes include `file.content`, systemd unit content,
browser/desktop values, arbitrary command argv, validation argv, provider
options, mount options, policy bodies, and script hooks as omitted secret or
sensitive content; credential, password-hash, private-key, certificate,
authentication, environment-secret, trust-anchor, and enrollment-token
references as secret references; SSH and certificate fingerprints as safe
fingerprints; and sensitive collections such as subjects, principals, hosts,
addresses, and paths as counts. Focused tests also prove that a secret cannot
use raw `value` projection and a public field cannot use `omit`.

### Task 3.3 agent sink-admission update — 2026-07-18

Raw provider `CheckResult.Actual`, provider-authored summaries, diagnostics, and
errors remain available only inside the provider execution/contract seam. The
agent engine no longer copies those values into a generic report. Instead, it
projects desired state from the registered per-field descriptors, represents
observed health with stable status/reason fields, and converts errors to a
closed `SafeError` without retaining the raw message or wrapped cause.

`SafeSummary` admits only valid class/projection/value-shape combinations,
bounds each text projection, validates again during JSON serialization, and
uses deterministic field ordering. Sync schema version 9 carries these typed
summaries for Check, Apply, child outcomes, and diagnostics; top-level Apply
failure telemetry carries the typed safe error. Version 8 added canonical
resource identity, and version 9 adds closed non-enforcing provider preflight
status and reason codes. Durable admission validates the complete version-9
shape before endpoint evidence can participate in plan derivation. Provider
descriptions in drift logs/reports are replaced by the registered public
resource kind.

The OS-AEC-074 canary test injects the same literal into malicious provider
desired/observed summaries, child summaries, diagnostics, and Apply error. It
asserts exact absence from the engine report, an operational error log, and
the authenticated Sync request. A separate registry test proves
`file.content` is omitted while public `kind` and classified path metadata are
retained by the schema-derived projector.
