# Applicator execution-contract migration inventory

Task 1.2 baseline, captured 2026-07-17. This inventory is deliberately broader
than the set that will ultimately become transactional: it records every
registered provider's observable rollback advertisement, every accepted
resource field, every generic exposure/persistence boundary, and every source
of a `changecontrol.FleetPlan`. Later tasks must update this inventory when a
provider is migrated or honestly downgraded.

## Rollback-advertising providers

`legacy best_effort` means the provider implements only `executor.Handler` and
therefore inherits the executor adapter's unconditional `best_effort` label.
That label does not prove that `Revert` can recover anything. `conditional
transactional` means the mutating path reports `transactional`, while an audit
or already-compliant path can report `none`.

The current `rollbackstore.Store` itself is also partial. It encrypts payloads
but activates `payload.bin` and `metadata.json` separately, uses one unversioned
root-file key, has no startup scan, and cleans by age/capacity without the full
attempt/success/supersession lifecycle. The connectivity providers add a
separate intent file around it. Tasks 2.1 through 2.6 own that shared-store
migration before the provider rows above can use a common transaction handle.

## Accepted resource fields

The canonical discriminator `kind`, identity `name`, and these shared metadata
paths are accepted for every resource:

`lifecycle`, `dependsOn[]`, `providerOptions`, `policy`, `ownership`,
`validation[].command[]`, `notifications[].type`, `notifications[].target`,
`preApplyValidation[]`, `risk`, `authorizationGroup`, `enforce`, and
`lockDomains[]`.

The table lists every remaining accepted path, including nested collection
paths. The current sensitivity value is the single whole-resource label from
`resourceregistry.Definition`; no field in any row has an enforceable field
descriptor yet. Consequently, even a `public` row can contain secret-bearing
content or references, while a `secret` row over-classifies its safe metadata.
Task 3.2 owns every row.

## Generic output, persistence, backup, and diagnostic sinks

| Sink/boundary | Current input | Current partial or unsafe behavior | Migration owner |
| --- | --- | --- | --- |
| Provider `Check` compatibility seam | `Handler.State() (any, bool)` and `CheckResult.Actual any` | Arbitrary observed values remain reachable. `RedactedSummary` is only a string alias with a caller promise; it has no schema-derived admission. | 3.3 |
| Provider Apply/result seam | arbitrary `error`, `DeferredWork.Summary`, `Diagnostics[]`, activation targets, rollback errors | Provider errors and summaries can carry command output or resource values. Validation checks shape, not sensitivity provenance. | 3.3 |
| Agent engine drift/apply reports | copied `RedactedSummary`, subresults, `ApplyFailure.Err` | The engine preserves nominal summaries but cannot prove their source; failure errors remain arbitrary. | 3.3 |
| Agent operational logs | formatted provider/activation/Sync errors | Redaction is call-site-specific. There is no sink type that refuses unclassified values. | 3.3 |
| Authenticated Sync request | `DriftPayload.Report`, `SystemInfoPayload.Report`, and `FirewallAuditPayload.Report` are `json.RawMessage`; failure/status messages are strings | Raw JSON and free-form messages cross the authenticated network boundary without schema-field admission. | 3.3, then 3.4 |
| Server Sync ingestion | raw telemetry is passed to `SyncTelemetry` after JSON decoding | It validates intent shape but does not project all generic telemetry through resource field descriptors. | 3.4 |
| Postgres state-report/system-info/firewall/apply-failure persistence | raw JSON and free-form strings in telemetry tables | Durable round trips trust the producer's redaction; restart does not add classification. | 3.4 |
| Change-control state persistence | one version-1 JSON blob containing requests, plans, hashes, effects, targets, leases, audit history, and break glass | `ResourcePlan.PredictedEffects` and related fields are arbitrary strings; persistence validates structure but has no classified sink admission. | 3.4 and 4.3 |
| Durable API audit log | `map[string]any` marshalled directly into Postgres JSON | Call sites choose details ad hoc; the sink accepts arbitrary nested values. | 3.4 |
| Admin API state-report/change-control/audit output | generic `writeJSON(any)` over stored models and raw reports | Responses rely on upstream discipline and can re-expose any unsafe durable value. | 3.4 |
| Operator CLI and desktop projections | generic JSON encoding plus hand-written text/detail formatters | Both consume server models/raw reports and have no independent classified projection contract. | 3.4 |
| Agent diagnostic archive | allowlisted commands, journals, `dmesg`, inventory, and raw agent `state.json` packed as arbitrary bytes | Size and collector allowlists exist, but collected bytes are not schema-classified; journals/state can retain a secret canary. | 3.5 |
| Diagnostic object storage/download | opaque tar.gz bundle plus digest/size metadata | Server stores and returns the opaque bundle; it cannot establish field-level safety after upload. | 3.5 |
| Database backup/restore | no Remotr application-level backup serializer or restore admission exists; operators back up Postgres externally | External backups faithfully retain unsafe raw JSON/string columns. | Rollback payload store | arbitrary `Record.Payload []byte`; metadata includes address, digest, attempt, state flags, expiry, nonce, checksum | Payload encryption exists, but sensitivity is a caller boolean and metadata/payload activation is split. | Adjacent file/download backups | arbitrary prior managed bytes beside the target | Unencrypted generic backup sink outside agent state, with no retention or classification. | 2.8 |

## `FleetPlan` producers and authoritative inputs

| Producer | Current source of plan evidence | Current partial or unsafe behavior | Migration owner |
| --- | --- | --- | --- |
| Admin API baseline-adoption handler | Decodes a complete client-supplied `changecontrol.FleetPlan` and overwrites only `Fleet` from the URL | Client-provided release ref, artifact digest, target compatibility/preflight, desired hashes, providers, effects, rollback classes, dependencies, and baseline eligibility are treated as authoritative. | 4.4-4.7 |
| Operator CLI baseline adoption | Decodes a user-selected JSON file into `admin.FleetPlan` and posts it | Local validation does not create trust; it is another caller-authored authoritative source. | 4.4 |
| Desktop baseline adoption | Parses, previews, clones, and posts a user-selected JSON `admin.FleetPlan` | Bounds and shape checks exist, but every security-relevant plan fact still originates in the selected file. | 4.4 |
| Secret activation coordinator | Constructs `FleetPlan` from `secrets.ActivationPlan.Uses` | Server-side construction exists, but hashes, provider, release/artifact identity, endpoint IDs, effects, and rollback class are copied or synthesized from activation inputs rather than derived from composed registered resources plus current endpoint evidence. | 4.1-4.5 |
| `changecontrol.Registry` | Consumes plans to create immutable requests, hashes, and dependency closure | It validates internal consistency only; it cannot establish that a supplied hash/effect/provider/target was derived at a trusted boundary. | 4.2-4.7 |

Tests create additional `FleetPlan` values as fixtures; they are not production
producers. Any new production constructor must be added here before task 4.4 is
closed.
